The RECNOS platform lets many client websites share one backend. Each client is a **tenant**: it has its own
forms, enquiries, team and website keys, and it can never see another tenant's data.

There are three ways people use it:

| Who | What they use | What they do |
|-----|---------------|--------------|
| **Platform operators** (RECNOS staff) | The **Superadmin** console | Create tenants, suspend and reactivate them. |
| **Tenant staff** (a client's own team) | The **Tenant dashboard** | Build forms, work enquiries, manage website keys. |
| **Website visitors** | A client's own website | Submit forms and enquiries, anonymously. |

## The pieces

- **recnos-setu** is the backend: a Java 21 service on PostgreSQL that holds all tenant data and exposes a
  versioned REST API.
- **The RECNOS site** hosts both consoles. The consoles never talk to the backend from the browser; the site's
  server forwards each request, so the backend's address and the session tokens stay out of page code.
- **The platform-admin service** is a separate process of the same backend, used only by the Superadmin console.
